# 스스로 판단하고 움직이는 로봇을 만들기까지

[README로 돌아가기](../../README.md)

## 주제를 정하기까지

이 프로젝트는 IoT 사물인터넷 수업의 과제 대체 프로젝트로 시작했다. 처음부터 로봇을 만들기로 정한 것은 아니었다. 시각장애인용 지팡이, 음주 측정기, 사람을 자동으로 감지하는 웹처럼 여러 주제를 검토했다.

그러다 Raspberry Pi와 LLM API를 연결하면 어떨까 하는 생각이 들었다. 미리 정해 둔 버튼만 누르는 차가 아니라, 사람이 말한 문장을 듣고 상황을 보고 다음 행동을 고르는 로봇. ‘스스로 생각하고 판단하고 움직인다’는 그림이 다른 후보보다 마음을 끌었다.

## 실제로 연결한 흐름

최종 통합본의 흐름은 다음과 같다.

1. USB 마이크에서 호출어와 한국어 명령을 듣는다.
2. Gemini가 명령을 허용된 행동의 JSON 순서로 바꾼다.
3. 프로그램이 행동명과 반복 횟수를 검사한다.
4. OpenCV 카메라, HC-SR04 거리 센서와 GPIO 모터를 필요한 순서로 사용한다.
5. 결과나 질문은 gTTS로 말한다.

카메라 질문과 물체 접근에는 Gemini Vision을 사용했다. 장면을 새로 촬영해 API로 보내야 하므로 입력부터 동작까지 시간이 걸렸다. 영상에서는 로봇이 멈춰 생각하는 것처럼 보이는 구간이 있는데, 실제로는 촬영·업로드·추론·응답을 기다리는 시간이다.

## 코드보다 어려웠던 실물

프로그램에 오류가 없다고 실물도 그대로 움직이지는 않았다. 배터리 전압이 떨어지면 모터 힘과 회전량이 달라졌고, 배선·USB 장치 번호·바닥 마찰·센서 방향처럼 코드 밖 변수가 계속 생겼다.

기술 문제와 별개로 ‘이게 정말 완성될까’ 하는 의심도 컸다. 주제는 눈에 보이게 크고, 어느 한 부분만 실패해도 전체 시연이 멈췄다. 그래서 배선, 모터, 거리, 카메라, 음성을 한꺼번에 붙이기보다 한 층씩 확인하는 방식이 중요했다.

## 안전 조건

전진 직전에는 초음파 거리를 다시 읽고 기본 25cm 이하라면 전진을 막았다. ‘장애물까지 이동’은 주행 중 거리를 반복해서 확인하고 기본 18cm에서 정지하도록 했다. 이 조건은 모델에게 적은 프롬프트만이 아니라 `hardware.py`의 조건문으로도 들어 있다.

다만 센서가 앞쪽 하나뿐이고 물리 긴급 정지 버튼이 코드에 포함된 것은 아니다. 그래서 이 구현을 완전한 자율주행이나 완전한 충돌 방지로 설명하지 않는다.

## 수업 발표

7월 9일 수업 시간에 실물 로봇을 발표했다. 원리를 이미 알고 있던 제작자와 달리, 보는 사람에게는 음성 명령을 들은 로봇이 카메라로 보고 움직이는 장면이 먼저 들어왔다. 반응은 AI가 처음 제품 시연으로 등장했을 때처럼, 내부 구조보다 눈앞에서 벌어지는 동작 자체에 집중되는 분위기였다.

## 영상과 공개 코드가 달라 보였던 이유

처음 저장소를 공개할 때 최종 통합본 대신 축약된 실험 코드가 올라갔다. 그 공개본에는 출력용 이동 스텁만 남아 있었고, 카메라·센서·GPIO가 주 실행 경로에 연결되어 있지 않았다. 이후 문서를 정리할 때는 공개 코드만을 근거로 삼았기 때문에 ‘영상의 기능은 현재 코드로 재현할 수 없다’고 정확히 적었다.

2026년 8월 9일, 5월 28일에 저장한 최종 발표본 `robot_pj_long_listen`을 다시 대조했다. 이 백업에는 영상에서 사용한 GPIO 모터, 초음파 센서, 카메라, Gemini Vision, 마이크 음성 인식과 TTS 흐름이 모두 연결되어 있었다. 그래서 다음 원칙으로 저장소를 복원했다.

- 최종 발표본의 Python 동작을 기준으로 삼는다.
- 폐기된 API 키가 들어 있던 과거 백업은 사용하지 않는다.
- 키 입력은 `.env`와 환경변수로만 받는다.
- 영상에서 실제로 한 기능과 코드의 현재 제한사항을 같이 기록한다.
- 7월 9일 축약 공개와 8월 9일 복원 사실을 숨기지 않는다.

이 과정에서 알게 된 것은 ‘공개된 저장소가 곧 제작 당시의 전체 기록’은 아니라는 점이다. 영상과 코드가 맞지 않을 때 기능을 추측해서 문서를 쓰는 대신, 보관본의 날짜와 파일 내용을 확인하고 차이를 남겨야 했다.

## 남은 개선점

현재 구현도 완성형은 아니다. 센서 타임아웃을 더 보수적으로 처리하고, 후방·측면 센서와 물리 긴급 정지를 추가하며, Gemini Vision의 지연을 줄이는 작업이 남아 있다. 하드웨어 없는 환경에서도 안전 조건을 반복 검증할 수 있도록 가상 장치 계층과 단위 테스트도 보강할 필요가 있다.
